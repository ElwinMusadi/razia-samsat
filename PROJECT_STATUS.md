## Architecture Decisions
Keputusan berikut APPROVED, bukan lagi usulan:
- AD-01: `VehicleSource` dengan `BpadPublicApiSource`. Worker memanggil BPAD Public API langsung: POST `https://dash.bpad.nttprov.go.id/pajak/webdtd/pendataan/core/php/getnopol.php`, JSON `{ "nopol": normalizedNopol }`. Browser tidak memanggil BPAD. PrivateApiSource/njkb-api-ntt Private API BUKAN bagian MVP.
- AD-02: satu deployment Cloudflare Workers + Hono + Workers Static Assets + D1 + KV. Tanpa Pages. API dan SPA fallback dipisahkan; `/api/*` tidak boleh mengembalikan app shell.
- AD-03: opaque session token acak kriptografis, SHA-256 hash di D1, cookie HttpOnly Secure SameSite=Strict, `__Host-` bila berlaku. OFFICER satu sesi aktif; ADMIN multi-session. Deactivation menginvalidasi sesi terkait. Tanpa JWT; auth flow diimplementasikan Phase 2. Endpoint/UI admin revoke spesifik tetap Phase 6.
- AD-04: plan Cloudflare/CPU belum diketahui; jangan mengasumsikan Free/Paid. Phase 2 memakai abstraksi PBKDF2 dengan parameter LOCAL/PROVISIONAL, bukan keputusan produksi final; wajib verifikasi plan/CPU dan parameter keamanan sebelum deploy.
- AD-05: security headers, request ID, no-store API, error envelope, safe logging; CSRF/auth/role middleware telah diimplementasikan Phase 2.
- AD-06: normalisasi NOPOL uppercase/hapus whitespace, validasi ketat tanpa diam-diam membuang tanda baca. WITA UTC+8; `today >= due_date` berarti EXPIRED termasuk hari H; `<` ACTIVE; missing/invalid UNKNOWN. Bukan aturan configurable `>`.
- AD-07: KV TTL 300 detik, hanya kendaraan ternormalisasi minimal (nopol, owner_name, brand, type, color, tax_due_date, stnk_due_date, provider_fetched_at), bukan raw/status terhitung. Source LIVE/CACHE dan fetched_at untuk freshness. Jangan cache error/malformed/NOT_FOUND. Strategi key hashed dapat dipertahankan; implementasi cache runtime Phase 3.
- AD-08: history mendukung FOUND dan NOT_FOUND; INVALID_INPUT sebelum BPAD tidak dicatat. Tidak menyimpan raw/field sensitif. owner_name diperlukan UI, bukan otomatis disimpan di check_logs. Logging asinkron dan observability Phase 5; heuristik siklus input belum disetujui sebagai aturan bisnis final.
- AD-09: nama DB, fields, API, identifiers, comments dalam English; UI/penjelasan dalam Bahasa Indonesia. Lane TEXT free-form, bukan INTEGER 1|2.
- AD-10: belum PWA UX/lookup offline. Nantinya app shell saja; tidak cache API di service worker/browser. Export CSV/XLSX di luar MVP.
- AD-11: Vitest + Miniflare/Workers test environment, TypeScript, linting; reuse pola teknis Kalkulator Pajak bila sesuai tanpa menyalin kebijakan cache publik.
- AD-12: tabel `locations` (dikonfigurasi admin), `users`, `user_sessions`, `raid_sessions` (`location_id` FK + `lane` TEXT), `check_logs`, `admin_audit_logs`; FK/integritas/indexes harus divalidasi. Petugas membuka sesi sendiri dengan lokasi existing. Satu raid session aktif per petugas. Sesi autentikasi single-device tidak diterapkan global.
- AD-13: provider HTTP/network/malformed/timeout adalah error, bukan status kendaraan. NOT_FOUND hanya dari verified response semantics, bukan HTTP 502. Katalog harus membedakan INVALID_INPUT, AUTHORIZATION_ERROR, INTERNAL_ERROR, UPSTREAM_ERROR, TIMEOUT, FOUND, NOT_FOUND dan status ACTIVE/EXPIRED/UNKNOWN. Pesan provider tidak diteruskan mentah.
- AD-14: minimization allowlist di batas adapter. owner_name boleh ditampilkan/cache minimal sesuai keputusan user; dilarang log/persist raw BPAD, NIK/KTP, alamat, BPKB, chassis, engine, NOPOL_EKS, Kohir, field lain yang tidak diperlukan. Tests menggunakan fixtures sintetis, bukan identitas nyata dari contoh user.
- AD-15: retensi mengikuti kebijakan organisasi bila tersedia; configurable, tanpa default periode bisnis dan tanpa automatic irreversible deletion sampai kebijakan dikonfirmasi.

## BPAD Response Facts
- User memberikan sampel nyata FOUND: flat object `kode="1"`, `status="success"`, NOPOL, NamaPemilik, Merk, Type, Warna, SD_NOTICE, SD_STNK. Raw payload memuat PII lain; jangan disimpan sebagai fixture/file/log.
- User memberikan sampel nyata NOT_FOUND: `kode="0"`, `status="failed"`, pesan berisi nomor polisi. Map ke NOT_FOUND dengan pesan aplikasi generik; contradictory/malformed metadata perlu validasi aman.
- DD/MM/YYYY dikonfirmasi user (contoh `07/10/2026`); successful sample juga berisi ISO YYYY-MM-DD untuk SD_NOTICE/SD_STNK. Parser menerima kedua format secara strict dengan validasi kalender; jangan Date.parse permisif, jangan dukung format lain tanpa bukti.
